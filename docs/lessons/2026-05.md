# Lessons — 2026-05

> Archivio mensile di `docs/lessons.md` (split D285, 2026-10-17). Formato e regole: `docs/lessons.md`.

- **[2026-05-04] [B247]**: Wall-clock timer derivation (`Math.ceil(remainingMs/1000)`) + `useEffect([secondsLeft])` gate + 1s `setInterval` is a fragile combination on iOS PWA: any tick drift can land outside the 1-s window and silently drop the beep. Counter-decrement was robust to drift but fragile to backgrounding (the original B67 trade-off). Correct pattern (already in 4 other timers in repo): sub-second tick (200 ms), in-tick check with `lastBeepedSecRef` dedup, reset on every phase transition. Open-threshold transitions (`remainingMs <= 0`) are robust; window-based gates need fine ticks + dedup.
- **[2026-05-05] [B248]**: Manually transcribed conversion tables drift from authoritative sources. The Font→V map in `gradeUtils.ts` was inflated by +1 across 5A..7A vs Wikipedia/Mountain Project standard, undetected for ~4 weeks because tests covered only 7A (which happened to be wrong) and a few other random points. Lesson: any conversion-table data should ship with a parametric test that pins **every** entry against the authoritative source on day one, not just spot-check a handful of values.
- **[2026-05-05] [A-NEW-MACRO]**: Quando un endpoint `/api/macrocycle/generate` poppa flag come `initial_tests_requested` (line 90), un nuovo endpoint che vuole settare quel flag deve farlo DOPO aver chiamato `generate_macrocycle()`, oppure (più pulito) NON passare per `/api/macrocycle/generate` HTTP-style: chiamare direttamente la funzione engine `generate_macrocycle()` e gestire flag/cache/save inline. La seconda strada evita coupling con la lifecycle del flag controllata da un altro handler.
- **[2026-05-05] [A-NEW-MACRO]**: Mappature di grade duplicate inline tra router (es. `_BOULDER_TO_LEAD` in `onboarding.py` linea 369-377) sono un debt nascosto: D232 ha trovato che `PUT /api/state` non applicava la stessa mappatura, lasciando `target_grade` stale dopo un discipline switch via Settings. Estrazione in `backend/engine/grade_mapping.py` con `BOULDER_TO_LEAD` + `LEAD_TO_BOULDER` (highest-boulder-per-lead per non sotto-stimare il livello sui tie) + helper `map_grade_for_discipline_change()` chiude il gap in un solo posto. Pattern: ogni mappatura semantica condivisa tra router DEVE vivere in un modulo engine, non inline.
- **[2026-05-06] [B-NEWMACRO-DEADLINE-FIX]**: `request()` in `frontend/src/lib/api.ts` formatta gli errori come `Error("API ${status}: ${body}")` — il body grezzo finisce nel `.message`. Renderlo direttamente in UI (`<p>{error}</p>`) leak technical detail. Pattern corretto: classifier puro `(err) → {userMessage, status}` con regex `^API (\d+):/`, distingue per status, ritorna copy user-facing; `console.error` per il debug. Refactor di `request()` per error tipato è out-of-scope — il regex contained funziona.
- **[2026-05-07] [B-NEWMACRO-STARTDATE-FIX]**: Decisione di design "evita overlap timeline" (`max(current.end_date+1, today)`) può sembrare conservativa ma in realtà rompe la UX quando l'utente ha un cycle ongoing lungo: clic "Start New Cycle" mid-cycle → date di inizio mesi avanti, utente senza piano in interim. Ogni volta che un dialog UI già comunica "discard / archive", la logica backend NON deve aggiungere wait semantics — l'archive **è** la continuity. Pattern: se la UI dice "ora", il backend deve fare "ora". Helper `strict_next_monday(today)` esisteva già in `start_date_utils.py:43` con la semantica giusta — bastava chiamarlo invece di reinventare `_next_monday_on_or_after` con `max(end+1, today)`.
- **[2026-05-07] [A218]**: Algoritmi di allocazione "default + flex absorber" senza cap superiori convergono su distribuzioni innaturali quando `total_weeks` cresce: lead a 21w produceva 12/4/2/2/1 con base inflated. Pattern corretto: per ogni risorsa allocabile, definire **floor**, **cap**, e una **priority list** per il riempimento del surplus. Il flex absorber prende quello che resta; non può mai superare il proprio cap. Simmetria per shortfall: reduce in inverse priority, never below floor. Senza questa struttura, l'algoritmo è "pseudo-determinista" — output formalmente coerente (sum corretto) ma semanticamente sbagliato.
- **[2026-05-07] [A218]**: Quando un'algoritmica esistente ha due funzioni quasi-duplicate (full vs incremental regen), preferire **una sola funzione con scope parametrizzato** (`phases=...`) rispetto a "due funzioni che condividono helper". I duplicati derivano sempre da costanti hardcoded ribattute (`_compute_remaining_durations` aveva `> 2` invece di `> shrink_floor`) — drift inevitabile. La consolidazione è più sicura del DRY tramite extract-helper, perché elimina il punto di drift invece di nasconderlo.
- **[2026-05-07] [A218]**: Tabelle di verifica scritte a mano nel design doc sono fonti di drift. Tre slip aritmetici nelle mie tabelle boulder (totals 14/15) sono stati catturati dai test entro 30 secondi (assert mismatch atteso vs algoritmo). Lezione: la suite di test è la ground truth, non la tabella; quando si specifica un algoritmo deterministico in un design doc, generare le tabelle dall'algoritmo (anche solo Python a mano) prima di fidarsi delle proprie sottrazioni.
- **[2026-05-10] [D236]**: Commit messages must match the diff. D197 labeled "archived to _archive/" while the diff was pure deletion — caused 4 broken citations and a missing audit doc. Always verify diff before commit when message claims a file move.
- **[2026-05-10] [B-SYNC-FIX]**: Regex anchored su free-prose ("1 app-level health check") fallisce silenziosamente quando il prose evolve ("2 app-level: health check + stripe webhook"). Preferire pattern strutturali stabili (`\d+ endpoints? total`) e sentinel test che asserisce match contro snapshot — il sync no-op silenzioso è invisible per definizione, serve un guardrail post-update che confronta header docs vs counter codice (RC-1 = bug latente per ~3 settimane).
- **[2026-05-10] [B-SYNC-FIX]**: Section-aware doc parser deve fermarsi a QUALSIASI sub-header, non solo a sibling/parent (`^#+\s` non `^#{1,depth}\s`). Una `#### Session-level optional fields` dentro `### 3.0 Canonical session template_ids` faceva leakare un field descriptor (`boulder_fallback`) come fosse un canonical id. Le sub-section non sono mai parte semantica della lista del parent.
- **[2026-05-26] [C239]**: `process_cues.json` ha un escaping non-standard non riproducibile con `json.dump(ensure_ascii=True|False)`: escapa i codepoint > U+00FF (em-dash `—`) ma tiene Latin-1 letterale (`Hörst`). Prima di appendere a un catalog "a mano" sempre verificare la convenzione con un round-trip byte-for-byte (riformatta l'esistente, confronta con il raw) — un append col setting sbagliato sporca il diff su tutte le righe.

Sempre **ri-eseguire `next_brief.py` o `grep` la roadmap subito prima del commit** — non fidarsi del numero preso in Phase 0. Catturato per un soffio prima di committare un ID duplicato.
